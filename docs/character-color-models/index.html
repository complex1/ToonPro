Character palettes and explicit recoloring

Define role-based colors and lighting variants, then preview a controlled raster replacement batch.

These instructions follow the current source build. Public 0.75 packages can differ.
In this chapterDefine approved colorsUnderstand palette changesPreview recoloringHow mapping behaves

Define approved colors

References → Color Models organizes named characters and color roles. Newly created characters receive Day, Night, Sunset and Interior variants. Additional variants begin as copies and can be edited independently; existing characters add missing variants explicitly. Variant colors share role IDs so later mapping identifies the same hair/skin/clothing role across palettes. Skin, Hair, Costume and Shadow tabs organize roles. Click a swatch or press Enter to copy it into the drawing foreground. Adding/renaming/moving/removing a role updates its identity consistently across variants; editing its color affects only the chosen variant.

Understand palette changes

Choosing a variant changes the approved palette used by compatible inspection workflows. It does not transform lighting or repaint old artwork automatically. Palette definitions are saved with their current native drawing/shot document; the selected variant is remembered for the open session and returns to Day on reopen. Global Colors palettes are a separate workspace library. Independent documents in the same dashboard do not automatically share these palettes.

Preview recoloring

Use Color Models → Recolor drawings. From is the palette already used; To is the replacement. Choose Current shot/All shots and check eligible raster drawings, including inactive animation drawings. Preview preparation runs off the UI thread. Before/After supports pan/zoom/fit; it shows raw source pixels before effects and surrounding layers.

  1. Define different source/target role colors first.
  2. Check the intended raster drawings.
  3. Generate Preview and inspect representative edges.
  4. Apply commits the whole batch as one Undo; Cancel leaves pixels unchanged.

How mapping behaves

Matching source RGB receives the target role RGB while retaining alpha. Supported narrow antialiased boundaries and premultiplied edges are remapped when their endpoints can be identified. Unrelated colors, broad gradients, unsupported mixtures and ambiguous role matches stay unchanged or require correction. Duplicate source RGB roles with different targets are reported. There is no cascading replacement or live palette-to-pixel link. Batches are bounded to 64 drawings and preview/storage budgets.
