## Reproduction

Run from the repository root after configuring the Qt/CMake build described in
the README:

```sh
cmake --build build --parallel 3
python3 -m unittest discover -s tests -p 'test_*.py' -v
ctest --test-dir build --output-on-failure --parallel 2
python3 scripts/capture_website.py --build
```

The focused high-DPI and native checks used:

```sh
QT_SCALE_FACTOR=2 ctest --test-dir build --output-on-failure --parallel 2 \
  -R '^(controls|drawing_tool_panel|brush_settings_panel|layer_panel|selection_panel|guide_panel|tool_navigation_panel|managed_project|reference3d_layer_panel|puppet_warp_ui|fill_reference_ui|perspective_dialog|canvas_mirror|cursor|drawing_tools_ui)$'
QT_SCALE_FACTOR=2 build/toon_controls_tests -platform cocoa
TOON_REFERENCE3D_NATIVE_CAPTURE_DIR=build/validation-2026-11-08/native-3d \
  build/toon_reference3d_native_integration_tests -platform cocoa
TOON_AUDIO_DEVICE_TEST=1 build/toon_audio_playback_tests \
  nativeSilentDeviceSmoke -platform cocoa
```

Four short sine fixtures were encoded locally with FFmpeg as MP3, AAC/M4A,
FLAC and Vorbis/Ogg, then decoded through the real application importer with
`TOON_AUDIO_FIXTURES=build/validation-2026-11-08/audio-codecs` and the
`compressedFixtures` case of `build/toon_audio_import_tests`.

The runtime smoke needs a new or empty output directory:

```sh
build/ToonPro.app/Contents/MacOS/ToonPro -platform offscreen \
  --package-smoke /tmp/toon-runtime-smoke-2026-11-08
```

Capture tooling requires the `cwebp` encoder. It builds its required capture
targets, runs real Qt widgets with temporary documents, and stores raw PNGs,
widget inventories and individual job logs under ignored
`build/website-captures/`. Curated lossless WebP files and their hashed index
live in `website/assets/screenshots/current/`. Each image records its dimensions,
relative source path, caption and provenance. The screenshots were visually
reviewed together after capture.

The project-gallery and line-conversion fixtures contain an imported sample
illustration. Their captions explicitly identify it as imported; it is not
evidence of artwork painted in Toon Pro. Other captures use synthetic sample
documents. No screenshot is a UI mockup.

The previous website artwork dependency was moved into
`tests/fixtures/managed-project/blue-hour.png`; project-management and optional
line-conversion captures now use that test-owned fixture. PNG is used because
this pinned Qt installation does not include a WebP image-format plugin. The
website's browser-facing images remain lossless WebP.

Every one of the 141 catalog entries now has a related thumbnail and an expanded zoomable capture; a 10-card showcase introduces the controls. Main documentation text measures 18 px desktop / 16 px mobile; the lowest representative contrast sample is **9.77:1**. The contrast sampling covers selected text roles and is not a full accessibility audit. Static checks at both base paths validate 42 HTML pages, 3,753 references, 141 thumbnails and 10 gallery images. The first readability-check run found that its lead selector also included smaller build metadata. Test review also found that navigation setup only opened the menu at the smallest width. Both test setup assumptions were corrected while preserving all size and contrast thresholds.

Evidence: `build/website-readability-browser/report.json`, `build/website-readability-static.json`, `build/website-readability-root-static.json` and `build/website-readability-review/`. The application results above belong to the earlier full run; this follow-up changes website files only and does not rerun or alter application behavior.
