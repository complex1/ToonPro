Build and run locally

Install the native toolchain, configure the Qt SDK, build the editor and run the project checks.

These instructions follow the current source build. Public 0.75 packages can differ.
In this chapterRequirementsConfigure and buildRun the editorRun checks and optional components

Requirements

Use CMake 3.24 or newer, a C++20 compiler, zlib and Qt 6.10 or newer. The maintained SDK pin used by local and packaging recipes is Qt 6.10.3. Required Qt modules are Core, Gui, Widgets, Svg, Concurrent, Sql, Multimedia and MultimediaWidgets. The SQLite driver is needed for managed project catalogs. Qt Test is needed when BUILD_TESTING is enabled.

On macOS the CMake deployment target defaults to macOS 13.0. Use the compiler and architecture matching the installed Qt SDK. Python supports development helpers, tests and packaging; Python is not the drawing editor runtime. See the repository packaging guide before distributing a build.

Configure and build

Run the commands from the repository root. Replace the Qt path with your installed platform SDK. The explicit Filament OFF setting avoids requiring its separate Apple Silicon Metal dependency; the current software-rendered reference-3D workspace remains separately enabled.

cmake -S . -B build \
  -DCMAKE_PREFIX_PATH="/path/to/Qt/6.10.3/platform" \
  -DTOON_ENABLE_FILAMENT=OFF \
  -DTOON_ENABLE_EXPERIMENTAL_3D=ON \
  -DBUILD_TESTING=ON
cmake --build build --config Release --parallel 4

Run the editor

On macOS open build/ToonPro.app. On Windows run ToonPro.exe from the selected build configuration. On other desktop builds launch the generated ToonPro executable. The app starts at Projects; a new project does not insert example artwork. Keep the complete .toonstudio directory together when moving it.

Run checks and optional components

Run CTest against the same build directory and configuration. Failure output identifies the affected suite. Review the current testing report for what was actually exercised on this machine; a successful source build does not verify a Windows or Linux installer.

ctest --test-dir build -C Release --output-on-failure --parallel 2
Keep in mind

The optional RIFE model/runtime has its own setup. Opening its panel never downloads a model.

TOON_ENABLE_EXPERIMENTAL_3D=OFF deliberately omits the approved reference workspace. The option retains its historical name.

Use docs/packaging.md and dependency notices for install/package steps; packaging does not publish a release.
