# 3D reference workspace

Status: **native drawing-canvas reference layers implemented, 7 November 2026**. Open **View → 3D reference…** or use the cube action in the editor toolbar. This opens the docked model/import/posing/material controls from the [Clip Studio Paint parity plan](3d-reference-replacement-plan.md). Full parity remains in progress; approval of these controls does not close the remaining requirements.

The compatibility-named `TOON_ENABLE_EXPERIMENTAL_3D` option defaults to **ON** after the artist's approval. Explicit **OFF** builds omit the new workspace and standalone review target. The old skeleton-building/weight-painting interface stays retired in both configurations. Existing saved legacy scenes retain their data and compatibility rendering.

## Open the workspace

The normal application opens a docked **3D reference** panel from **View → 3D reference…** or the editor toolbar cube action. **Library** contains Models, Poses and Materials; **Controls** contains the reviewed object, pose, shape, face and camera settings. A separate review build remains available for isolated testing with the installed Qt SDK:

```sh
cmake -S . -B build-3d-review \
  -DCMAKE_PREFIX_PATH="/path/to/Qt/6.10.3/platform" \
  -DTOON_ENABLE_EXPERIMENTAL_3D=ON -DBUILD_TESTING=ON
cmake --build build-3d-review --target ToonPro3DReview ToonPro --parallel 4
```

Open **Toon Pro 3D Review** to enter the workspace directly. On this Mac the bundle is `build-3d-review/Toon Pro 3D Review.app`. It has a separate application/settings identity and does not open a production project. The normal app uses the drawing canvas for its native reference layers; the standalone app remains an independent scene workspace for isolated inspection.

Models are decoded lazily in the thumbnail worker; placing an uncached catalog model waits for that worker and adds one Undo operation.

The normal editor owns each native 3D scene inside its drawing layer and uses the drawing’s Undo history. Models, poses, morphs, expressions and scene cameras remain editable after project save/reopen. The standalone review app retains its own scene and history. Its target is absent from explicit OFF builds.

## Current workflows

1. Open a drawing, click the cube action and choose **Models** in **Library**. Select a model and click **Place model**, double-click or press Enter. If a reference layer is selected, placement adds to that scene; from an artwork layer it creates a new reference layer. **New 3D** and the Layers cube action create an empty reference layer explicitly.
2. Select the reference layer and use **Translate**, **Rotate**, **Scale**, **Pose** or **Camera** above the library. **All / X / Y / Z** chooses free/uniform or constrained manipulation. Drag the model or a joint on the actual drawing canvas. Precise controls, existing pose presets and supported finger/shape/expression controls edit the same scene.
3. Click **Draw above** to add and select a raster layer above the reference and return to Brush. The 3D render has a transparent background, so artwork below it remains visible. Draw freely on the raster layer; selecting it removes 3D handles and returns input to the drawing tools. Select the 3D layer again to continue posing.
4. Use normal layer ordering, opacity, visibility and locks to compose the reference with the drawing. Native source data is protected from pixel painting, merging or accidental raster flattening. Direct reference-layer filters/masks remain unavailable; containing folder compositing follows the shared renderer.
5. Save the drawing/project normally. Its revision retains the complete editable reference scene and models, rather than only the rendered image. A completed pose/object/camera gesture is one drawing Undo operation; Escape cancels the active canvas gesture.

The detailed controls below also remain available in the standalone workspace.

- Open **Models** and choose **Body**, **Head**, **Hand**, **Anime** or **Pets**. Anime contains Seed-san and Alicia; Pets contains a rigged dog, cat and eagle. Search the 20 supplied proportion presets: four figures, nine heads and seven hands. Select a thumbnail and choose **Place model**, double-click or press Enter to place it. These share a CC0-derived anatomical base with Toon Pro shape recipes; see [model sources and limits](3d-model-library.md) and the [retained MakeHuman/MPFB provenance](../third-party/makehuman/README.md). Imported GLB/glTF/VRM characters remain available through the toolbar's Import action. Extreme anatomy/deformations and the wider parity requirements remain subject to further artist acceptance.
- Select objects in the scene list or drawing canvas. Change placement, visibility and lock state; duplicate or remove objects. Navigate the camera with orbit/pan/dolly, fit the scene, and switch parallel/perspective projection.
- Open **Poses** to browse 20 original body presets and 11 hand presets, with category tabs and search. **Apply pose**, double-click or Enter applies the selected recipe in one Undo operation while retaining model shape, placement and expressions. Body categories include standing, seated, ground, movement, balance, reach and action. Hand poses can target **Both**, **Left** or **Right**; **Mirror** swaps a single hand target or mirrors the body recipe. Both-hand recipes already use mirrored sides. Thumbnail rendering and browsing do not edit the scene or history. These are Toon Pro recipes, independent of CSP's pose files or asset catalog.
- Selecting a pet switches the preset browser to its matching static animal poses. These apply the original rig's local joint transforms in one Undo operation and preserve object placement; humanoid hand controls are unavailable for these rigs.
- In **Pose**, rotate individual joints using local handles or exact controls. A connected hand/foot endpoint also supports two-bone **IK** with target/pole controls. The solver preserves imported rest orientations and clamps unreachable targets. It currently requires positive uniform scales on the relevant chain and reports unsupported cases instead of altering the rig incorrectly.
- In **Pose → Hands**, select both hands or one side, then **All** or an individual finger. **Curl** and **Spread** offer sliders and exact entry; **Reset fingers** opens the selected fingers without changing the wrist or body. Values are fitted from the actual joint pose, and custom or mixed poses are identified. Editing one channel preserves the other channel independently on each hand. These controls require a complete mapped hand and do not infer an absent skeleton for an uploaded mesh.
- In **Shape**, use the figure's **Build/Definition** pad or region tabs for body, torso, limbs, head features and hand details. Sliders retain exact entry. The nine-head and seven-hand **mix** pages offer weighted Toon Pro shape recipes and direct preset buttons; **Limit** normalizes combined weights above 100%, while lower totals retain the base form. Figures expose both families, and separate head/hand studies expose the relevant family. Head regions include chin, eyes, brows, nose, mouth, ears and neck, including supported left/right details. Hand controls include palm, wrist, nails and individual finger proportions; standalone hands have explicit **Left/Right** model tabs. Geometry, skeleton rest positions and inverse binds are regenerated together, preserving the pose and placement. Switching a hand's side reflects its existing pose.
- Edit an imported model's actual morph targets and named morph expressions. Expression amounts persist separately from base shape weights; overlapping expressions combine in the evaluator. The supplied figure/head have Smile, Blink and Jaw open examples. No missing morph or expression is invented for an uploaded model.
- Native reference layers save with their drawing/project. The scene toolbar additionally imports/exports self-contained **`.toon3d` scenes**. Register and reuse scene, character, body/hand pose, compatible body/head/hand shape and camera materials. Search/filter materials and toggle favorites. Pose application preserves target placement and uses semantic rest-relative rotation mapping when the source and target differ.
- Closing a drawing tab, editor or project uses the drawing’s Save/Discard/Cancel decision for its native reference layers. Optional independent reference windows retain their separate `.toon3d` Save/Discard/Cancel handling.
- Undo/redo document edits, commit one operation per drag, or cancel an active gesture. Native scene-camera edits use drawing Undo; standalone camera navigation stays outside object/pose Undo. Save resolves pending exact entries; opening another scene and closing a dirty window use Save/Discard/Cancel.

## Import and source fidelity

The new importer is independent of the old static-only importer. It preserves node hierarchy and local TRS/quaternions, skin joint ordering/inverse-bind matrices, normalized weights, sparse morphs, normals/tangents/vertex colors, core material parameters and texture images. VRM0/1 humanoid mappings and morph-expression bindings are adapted to the canonical schema; original indexed extension metadata, usage metadata and image payloads remain self-contained.

This is **partial VRM behavior**, not a blanket VRM compatibility claim. MToon shading, gaze, constraints, spring physics and material-expression bindings are retained/reported where present but are not all evaluated. Imported diagnostics remain available on the selected model after save/reopen.

The initial importer accepts at most four nonzero influences per vertex without truncation. Unsupported animations, sheared matrix nodes, extra scenes, required extensions and other unsupported source semantics are rejected explicitly. FBX/OBJ/STL/LWO, BVH and native CSP/ASSETS material compatibility are not implemented in this slice. The source-linked parity plan keeps those workstreams open.

The parser uses pinned **cgltf v1.15** with the [vendored provenance and MIT license](../third-party/cgltf/README.md). File resources are local, bounded and constrained to the source directory; imports do not resolve arbitrary network URLs. Cancellation and stale async completion do not publish a partial model.

## Preview fidelity and assets

The drawing canvas and standalone viewport share an asynchronous, depth-tested software renderer with perspective-correct base-color texture/vertex-color interpolation, simple directional/ambient shading, alpha handling and object picking. The persistent **Base-color preview** label identifies this limit. Canonical normal/metallic/roughness/occlusion/emissive textures and avatar shader metadata are preserved, but this viewport does not yet reproduce those shaders or CSP's final rendering modes. A 192 MiB evaluated-preview work budget rejects excessive repeated geometry before expansion; the scene remains intact and can be simplified or saved.

Translate, rotate, scale and camera gestures continuously publish completed previews while retaining only the latest pending request. Moving an object or camera reuses cached posed geometry; joint, morph and expression edits invalidate that geometry. Interaction previews fit within 640 × 480 pixels, then refine to the normal 1280 × 960 maximum on release, cancellation or a 120 ms input pause. Scene values and saved geometry retain full precision throughout, and one completed object gesture remains one Undo command. Picking waits for a coherent scene/frame pair after replacement or an unfinished update. The worker-local geometry cache has a separate 128 MiB limit.

Native transparent preview images use one background worker with a latest pending request and a bounded 64 MiB display cache across visible reference layers. Drawing on a raster layer reuses those images. Export rendering regenerates images from the canonical scene and samples large artwork at a bounded 4096-pixel edge / 16-megapixel image budget; the drawing retains full model and pose precision. This is not GPU skinning or a production-latency certification.

The old Filament service remains available for existing scene compatibility. A renderer-neutral bridge can supply evaluated new triangles for validated supported materials; it does not synthesize old rigs or skin bindings. GPU skin/morph rendering, PBR/MToon fidelity, proper shadow/contact controls and production-scale latency remain explicit acceptance work.

The anatomical studies use a continuous base derived from CC0 MakeHuman/MPFB graphical assets, with Toon Pro regional shape definitions, nine-head/seven-hand mixture recipes and original pose recipes. Source attribution and adaptation details are retained in [third-party/makehuman](../third-party/makehuman/README.md). The separate Anime/Pets catalog adds prepared official VRM sample characters and Quaternius animal models; see [the model library](3d-model-library.md). No CSP or Tripo model is bundled. Model/pose thumbnails render the actual supplied geometry asynchronously at a bounded size. This provides the approved drawing-reference library; it does not certify final anatomy, anatomical accuracy, skin corrections, clothing/hair editing, library scale or equivalence to CSP's authored model families.

## Persistence and material ownership

`reference3d.h/.cpp` defines the canonical model/pose domain. Native `Reference3D` layers were introduced in project format **41**; later formats can also carry them alongside other features. The project stores a shared, content-addressed table of compressed canonical model assets and small per-layer scene state, so different poses/layers can share a model without repeating its payload. Native files and managed project revisions retain this data, including saved/recovery revisions. Existing legacy scene interpretations are unchanged. Resource/count limits and SHA-256 checksums validate the data before publication. Scenes embed content-addressed immutable assets once and retain independent instance placement/pose/expression state. Unknown versions, corrupt resources and invalid hierarchies fail before publication.

The material library has an atomic manifest and content-addressed self-contained payloads. Registration holds a library lock, rejects stale writers before publishing payloads, and enforces entry/storage budgets. Loading payloads checks their hashes. Removing a material reclaims only its unreferenced library-owned payload; placed scenes and other materials keep their own/shared data. Schema checks prevent a hand model from being registered as a head-shape material. API support for renaming/tagging does not imply dedicated rename/tag controls in the current browser.
