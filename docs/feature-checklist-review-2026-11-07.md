# Toon Pro — feature checklist review and development options

**Review date:** 7 November 2026 · **Implementation follow-up:** 8 November 2026 · **Application:** current local 0.76.0 source · **Purpose:** discussion and prioritization

**Implementation update:** Canvas mirroring, adjustable fill expansion, active-layer intersection erasing, line-art Enclose fill, an ellipse snapping assistant and local Vector Nudge are implemented locally. Brush stabilization now has zoom-consistent Smooth and stronger Stabilizer modes, dead-zone tuning and ordered finishing. The original audit found 55 implemented /28 partial /19 missing /1 hidden feature; the current matrix has **60 implemented /24 partial /18 missing /1 hidden**. Nudge/slice remains Partial because arbitrary slicing is absent. See [Drawing tools](drawing-tools.md), [stabilization research](stroke-stabilization.md) and [the development log](DEVELOPMENT.md) for controls, limits and verification. Public 0.75 packages are unchanged.

This document compares all **103 features** in the supplied Artist Pro checklist with Toon Pro, identifies useful gaps, and proposes additions supported by product research. The original review was reference-only. The subsequent drawing improvements were separately authorized and implemented; remaining proposals are discussion options.

## 1. Recommended direction

**Build on the drawing tools already present, finish the most useful incomplete interactions, and prove the workflow with the artist before expanding into a larger animation system.** Mirroring, fill expansion, intersection erasing, enclose fill, ellipse assistance, local nudge and stronger stabilization are now implemented. Physical-tablet/recovery acceptance remains important. Layered interchange, semantic palette links and camera-linked drawing references remain follow-on options.

The current source has substantial raster/vector drawing, brush dynamics, layers, masks, selections, perspective guides, character palettes, cel-color checking, frame-by-frame animation, audio, Symbols and local project management. Several items that sound like new features are already available and need evaluation or refinement. Advanced rigs, automatic lip sync, secondary-motion physics, node compositing and a complete movie-review pipeline are much larger gaps.

Three boundaries matter when reading this review:

1. **Current source differs from published packages.** The README identifies the local work as 0.76.0 and the public preview as 0.75.0. This review audits the working tree, including existing uncommitted work. It is not an audit of the downloadable 0.75 package.
2. **An implemented code path is different from production acceptance.** Source, UI routing and test coverage establish that a capability exists; they do not establish tablet feel, real-time performance on the artist's hardware, or completion of a representative production shot.
3. **Current drawing priority governs recommendations.** The supplied project instructions prioritize drawing and UX and defer new animation work. A historical paragraph in `ui-guidelines.md` says animation resumed on 2 November; that does not override the current instruction. Animation gaps are recorded for later review.

In older engine terminology, a “project” can mean one native `.toonproj` payload. Current managed `.toonstudio` projects contain independent drawing/shot documents. A Symbol or character palette saved inside one payload is not automatically a shared library across those documents.

## 3. Ranked options for the drawing-focused phase

These are product judgments based on workflow fit and the inspected code, not measured productivity claims. **S** means a bounded extension to an existing interaction; **M** spans several UI/model/test paths; **L** adds significant storage, rendering or dependency behavior; **XL** introduces a substantial subsystem. These are relative sizes, not time or staffing estimates.

| Rank | Candidate | Why it is useful | Feasibility and dependencies | Evidence required before calling it finished |
| --- | --- | --- | --- | --- |
| 1 | **Prove pen feel, long-session performance and recovery** | Every other tool depends on strokes arriving correctly and artwork surviving interruptions. | **M, now.** Existing input, benchmark, save/recovery and backup foundations. Device/OS acceptance is the main work. | Actual tablet: slow diagonals, fast circles, pressure/tilt, eraser switching and interrupted strokes while saving. Reopen recovered and backed-up work and compare pixels/state. Record p95/worst latency and memory on named hardware. |
| 2 | **Instant view-only mirror — implemented 8 November** | A frequent proportion-checking action for faces and poses, with no artwork edit. | **S–M, now.** Add a view transform and direct shortcut; audit inverse coordinates across all tools. | Two toggles restore the view; brush, guides, selections, sampling and 3D handles follow the cursor at rotation/zoom. Saved pixels, export and artwork Undo remain unaffected. Krita documents the same kind of view action. [View manual](https://docs.krita.org/en/reference_manual/main_menu/view_menu.html) |
| 3 | **Erase vector strokes up to intersections — implemented 8 November** | Removes cleanup overshoots without manual cutting at every crossing. | **M, now.** Existing vector geometry, slicing and correction are useful foundations; calculate geometric intersections rather than equating a Bézier segment with a visible span. | Preview and erase the intended interval on curves, self-crossings, overlaps and near tangencies; preserve width/pressure/style; define whether other visible vector layers count. One gesture equals one Undo. [CSP vector eraser](https://help.clip-studio.com/en-us/manual_en/180_layers/Vector_layers.htm) |
| 4 | **Enclose-and-fill, adjustable expansion and clear fill feedback — implemented 8 November** | Fill several regions in one gesture; spend less time fixing leaks, white seams, missed hair tips and unintended sampling. | **M, now.** Extend existing bucket boundaries, gap controls, fixed antialias-edge recovery and Paint Check. Enclose/multi-region fill and explicit growth/shrink are new behaviors. | One enclosure fills only intended closed regions; growth preserves line cores; artist sees the sampled source and affected region; cancel stale/large jobs; compare thin/gapped/antialiased art at 100%; one Undo. [CSP Fill manual](https://help.clip-studio.com/en-us/manual_en/420_fill/Fill_Tool.htm) |
| 5 | **Direct post-fit shape handles; ellipse guide implemented 8 November** | Refine eyes, cylinders, props and construction geometry after a rough gesture. | **M, remaining.** The editable standalone ellipse snapping assistant is implemented. Immediate handles on a hold-recognized shape are still separate; recognized vector strokes support Path Edit. | Evaluate ellipse capture and editable axes with the pen. Future fitted-shape handles should preserve style, source, save/reopen and Undo. |
| 6 | **Semantic palette links** | Change an approved hair/skin/shadow role without repeatedly matching RGB values across drawings. | **L–XL, next; prototype-dependent.** Existing named roles, variants and previewed batch recolor are a starting point. Persistent color identity requires region/stroke metadata or a separate indexed representation and migration policy. | Two identical RGB values with different roles remain independently editable; variants preview across selected uses; preserve antialiasing; offer detach/bake and one-step Undo. Harmony documents stable swatch IDs and clones as a reference. [Colour menu](https://docs.toonboom.com/help/harmony-24/premium/reference/menu/view/colour-view-menu.html) |
| 7 | **Layered interchange with an explicit supported subset** | Bring line, paint and background layers into or out of tools artists already use. | **M–L, next.** Start by evaluating OpenRaster for raster stacks; assess PSD separately. Translate groups/opacity/blending carefully and report unsupported constructs. | Round-trip fixture documents through a named second app; compare composite and layer data; preserve alpha and offsets; give a conversion report for masks, vectors, live effects and native 3D. OpenRaster stores layers as PNGs in a ZIP/XML container. [Krita OpenRaster](https://docs.krita.org/en/general_concepts/file_formats/file_ora.html) |
| 8 | **Camera-linked perspective guides and safer 3D paint-over** | Keep constructed lines consistent with the 3D view and reduce layout drift. | **L, next.** Native reference3D camera and 2D guides exist independently. Define which camera owns the drawing layout and how users intentionally lock it. | Project guide vanishing points from that camera; drawing and imported props agree at edges of frame; explicit camera lock/reset; save/reopen and export match; no silent reprojection of painted pixels. |
| 9 | **Visible resource budgets and export checks** | Explain a refusal before a large operation fails; reduce missing-media, reference-visibility and output-setting mistakes. | **M, next.** Reuse existing validators, tile/resource limits, media metadata and export settings. | Predict storage/tile demand, including retained warp sources; show dimensions, transparency, range and included reference/Notes state; open and compare a sample output. Checks should expose actionable issues, not add mandatory clicks to routine drawing. |
| 10 | **Local nudge implemented 8 November; deliberate slicing remains** | Push a small contour into place without manipulating many individual nodes. | **Nudge implemented.** Radius/strength and pen pressure deform a source snapshot locally, retaining recorded brush data. Arbitrary artist-controlled cuts are still separate work. | Evaluate contours, pressure and Undo on actual vector drawings. Unreliable curved-symmetry inverses refuse atomically; path-morph sources are blocked. |
| 11 | **Editable color hints for flats** | A few scribbles can describe desired colors across many enclosed regions, while retaining corrections. | **L, experiment.** Separate hint data from source line art and generated paint; reuse background jobs and guarded publication. No cloud service is required by this proposal. | Correct one hint and regenerate; show ambiguous/leaking regions; handle transparency; retain hints on reopen; cap processing; keep source untouched. Krita's Colorize Mask shows the workflow and its performance/animation limits. [Colorize Mask](https://docs.krita.org/en/reference_manual/tools/colorize_mask.html) |

**Current review batch:** test the implemented drawing improvements on one demanding illustration, with special attention to pen feel in Smooth versus Stabilizer. The original ranking remains for context, with delivered scope marked above. Post-fit shape handles and deliberate slicing remain smaller candidates; palette links, interchange and camera synchronization deserve prototypes before a commitment.

## 4. Additional possibilities from online research

Official product manuals were checked on **7 November 2026**. They demonstrate workflow patterns; they do not prove that copying them is cheap or that Toon Pro has performance parity. The proposed scope and ordering below are our inference from those sources and Toon Pro's current architecture.

| Addition or refinement | Current Toon Pro position | Suggested scope and benefit | Decision |
| --- | --- | --- | --- |
| **Color-managed import, display and export** | Rendering/export code tags several images as sRGB and native 3D texture identity retains ICC data. No complete user-facing ICC/display-transform or soft-proof workflow was found. | Begin with explicit source-profile handling, conversion policy and consistent display/export interpretation. Add soft proof and gamut warnings only if print is an artist need. Color tagging alone is insufficient evidence of a complete pipeline. Krita documents per-view soft proofing and saved proof profiles. [Soft proofing](https://docs.krita.org/en/user_manual/soft_proofing.html) | **Strong next; L.** Useful for dependable illustration delivery; full HDR/CMYK authoring is a separate decision. |
| **Asset usage, pinned versions and reviewed updates** | Project-owned imports and editable native items exist; automatic usage tracking, relinking, cross-project libraries and live linked placement are explicitly absent. | Start with “used by,” missing-source reporting and attribution/source metadata. Then prototype linked placement with a pinned revision, update preview and detach. Blender's override model demonstrates the need to distinguish shared source from local edits and handle dependency changes. [Library overrides](https://docs.blender.org/manual/en/5.1/files/linked_libraries/library_overrides.html) | **Strong next; M for reporting, L–XL for linking.** Do not combine both into one small task. |
| **Named saved checkpoints and visual comparisons** | Current save, previous save and recovery revisions are retained under bounded policies; history is not a named, persistent review system. | Let an artist name an approved drawing state and compare before/after without losing the current version. Persistent retention is a new policy, not implied by existing revision files. Krita's snapshots illustrate state selection, but its documented snapshots disappear on document close. [Snapshot Docker](https://docs.krita.org/en/reference_manual/dockers/snapshot_docker.html) | **Useful next; M–L.** Explicitly distinguish checkpoints, recovery and backup. |
| **Pen-friendly on-canvas quick palette** | Inline colors, tagged tools and customizable Quick Access already exist. A radial/popup brush/color/history surface was not found. | Prototype an optional shortcut-invoked palette for favorites, recent colors and view actions. Measure pointer travel and accidental activation against current controls. Krita documents these controls together. [Pop-up Palette](https://docs.krita.org/en/reference_manual/popup-palette.html) | **Optional experiment; M.** Add only if the artist prefers it. |
| **Wrap-around texture painting** | Brush textures and materials exist; a wrap-around canvas/edit mode was not found. This is also checklist S08, so it is a refinement rather than an extra checklist item. | First provide repeat preview; then wrap paint/erase footprints across canvas edges with correct Undo and selection behavior. Useful for fabric and background materials. [Krita View menu](https://docs.krita.org/en/reference_manual/main_menu/view_menu.html) | **Specialist next/later; M–L.** Lower value than cleanup for character-focused work. |
| **Storyboard/animatic planning in the organizer** | Current Movie projects organize independent documents. Retained legacy review code does not provide a normal managed-project sequence editor. | If animation resumes, prototype ordered panels, shot duration, dialogue/action/camera notes and PDF board export, then audio-backed animatics. Krita documents panel ordering, comments, duration and document export. [Storyboard Docker](https://docs.krita.org/en/reference_manual/dockers/storyboard_docker.html) | **Later; L–XL.** Keep it outside the drawing canvas. |
| **Artwork timelapse capture** | Macro-like Auto Actions and Motion Study exist, but neither records the evolving artwork into a timelapse. No recorder was found. | Optional background snapshots with a visible recording state, bounded storage and export. Useful for teaching and sharing process; never allow recording work to stall pen input. Krita documents snapshot capture and its disk/performance costs. [Recorder Docker](https://docs.krita.org/en/reference_manual/dockers/recorder_docker.html) | **Optional later; M.** Lower production value than recovery or interchange. |

### Useful ideas to defer

| Larger option | Potential benefit | Why it should wait / what must come first |
| --- | --- | --- |
| Smart Bone-style corrective controls and a true 2D deformation rig | Reusable expressive body/facial animation. | **XL.** Needs a coherent 2D rig model, editable weights, dependency evaluation, timeline channels and storage. Existing static puppet pins and retired 3D rig code do not supply that workflow. |
| Editable stroke matching and assisted inbetweening | Artist-controlled intermediate line drawings. | **XL.** Needs explicit identity/correspondence, topology changes, occlusion and correction tools. Compatible path morphing and RIFE optical-flow output cover different, narrower cases. |
| Temporal color propagation | Reuse approved flats across related animation drawings. | **L–XL.** Needs stable palette identity, correspondence/confidence, occlusion handling and manual correction. Start only after single-drawing fill is trusted. |
| Automatic lip-sync suggestions | Faster dialogue blocking with reusable mouth drawings. | **L.** Build on manual mouth frames and audio; add phoneme/viseme mapping, language support and easy overrides. No automatic system was found in the current app. |
| Hair/cloth physics and animation retargeting | Less repeated secondary motion and rig setup. | **XL.** Requires an accepted animation rig and deterministic preview/export. Static imported model posing is insufficient. |
| Node compositing, expression language and procedural FX | More sophisticated finishing and reusable effects. | **XL.** Adds a graph/evaluation system, validation and resource management. Existing layer effects, masks and animation channels should be evaluated first; specialist downstream tools remain a practical handoff. |
| Cloud collaboration and a global asset service | Shared review and materials across people/projects. | **XL plus ongoing operations.** No current shared-state service exists. Local project safety, portable exchange, asset identity and review semantics should precede it. Online research does not require artwork upload or a cloud backend. |

## 5. Suggested sequencing and review criteria

| Phase | Outcome | Candidate scope | Exit condition |
| --- | --- | --- | --- |
| **A — Validate the present drawing workflow** | A dependable path from sketch to saved/exported illustration. | Actual pen acceptance, recovery/backup rehearsal, cleanup/fill usability and current reference3D testing. | Artist completes and corrects a representative layered drawing; save/reopen and exported appearance agree; observed blockers are recorded. |
| **B — Finish frequent drawing interactions** | Fewer interruptions during construction, cleanup and flats. | Mirror, smart vector trimming, enclose-fill/expansion/feedback, editable shapes/ellipse guides. | Artist can complete repeated real tasks with fewer corrective actions; no input, Undo or storage regression. |
| **C — Improve reuse and handoff** | Consistent approved colors and reliable movement between tools. | Palette identity prototype, bounded layered interchange, camera-linked guides, resource/output checks, profile policy. | Round-trip artwork and reuse tests pass against named apps, source types and limits. |
| **D — Return to animation deliberately** | A validated short shot before expanding the animation feature set. | Existing timeline, trace, Symbols, audio and export first; then choose between inbetween assistance, rigging or boards. | Complete a shot with one review correction and verify timing, audio, transparency, camera and reopen. No new animation work is implied by this document. |

Do not set a release date from this table. Prototype and artist-review results should determine the next scope.

For each selected candidate, write a one-page brief with: the exact artist task; present workaround; minimum useful behavior; affected file/UI paths; source/Undo/save policy; resource bounds; platform acceptance; and an observable success criterion. Follow [the UI rules](ui-guidelines.md): direct frequent actions, accessible icon names, the shared 600 ms tooltip delay, appropriate interactive widgets, category tabs and semantic neutral theme tokens. Current user instructions supersede historical blanket control rules.
