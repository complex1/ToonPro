# Architecture

## Boundaries

`toon_core` holds project data, validation, JSON persistence, sheet geometry and image exports. `toon_workspace` holds the desktop shell, setup dialog, canvas view and Navigator. `ToonPro` is the executable entry point. `toon_tests` links the same libraries as the application.

The sheet renderer now composites tiled raster layers. `Document` owns the authoritative Project and undo history; Canvas owns only tools and working-view state. Drawing panels issue document edits. Sheet, movie-frame and Navigator rendering use the same layer compositor.

## Drawing UI

`ui_theme.h/.cpp` defines shared Adobe Spectrum dark color roles and the application style. A Fusion proxy provides a 600 ms tooltip wake-up delay with no instant-reshow grace; an application help filter fills missing button labels and suppresses help during mouse or pen interaction. Embedded Lucide icons reuse palette-aware rendered pixmaps. Artwork and sheet rendering never read these theme tokens.

`BrushSettingsPanel` keeps five drawing-time scalar controls and a pressure-size toggle inside Tool Properties. Its wrench opens one owned, window-modal `QDialog` containing the existing eleven-category icon tab rail. Both views edit the same Canvas settings live, independently of artwork history; the active advanced category remains saved in the existing workspace INI. Quick controls refresh immediately; hidden advanced bindings, tip lists and texture previews refresh on reopening. The modal retains its tab/scroll positions, has a non-default Close button and parents nested file/color dialogs. Closing keeps committed settings and returns focus to Canvas. Tool unavailability or leaving brush/eraser closes a visible advanced dialog. `BrushVisualWidget` edits spatial brush settings and caches local previews; compact fields stay synchronized through Canvas brush signals. `ColorPanel` edits foreground/background colors directly through an HSV field and Hex input. Tool, reference, layer and selection actions use explicit tooltips and accessible names. Layer-row flags commit through Document while preserving the active drawing target. Selection modes use exclusive direct actions; transform precision fields complement existing canvas handles. The baseline save format 19 covers typed drawing templates, vector cels, custom easing, spatial tangents, orientation, effects, masks, adjustments, camera poses/keys, audio clips/resources, property channels, vector path poses, drawing exposures and templates, embedded 3D reference models, instance rest skeletons, skin weights and poses, retaining editable brush sources/resources, raster/vector/text objects and saved selections. Colored vector-stroke resources require format 20 and extended brush dynamics require format 21. Multiple shots or nondefault scene names select format 22; any nondefault audio-finishing metadata selects format 23 and retains required scene metadata. Source brush libraries select version 3 for colored presets or version 4 for extended dynamics. Tool catalogs now write version 8, including the one-time standalone Text migration.

`LayerPanel` keeps a compact properties header and action footer outside its scrolling `LayerTree`. A custom delegate paints 44 px rows with checkerboard thumbnails, names, folder hierarchy, lock/status markers and row colors. The tree owns transient extended selection, expansion, scrolling and drag indicators; it sends stable layer IDs to Document for actual moves. Above/below drops show a 3 px insertion line; dropping into a folder outlines its row. Double-click editing uses an inline name field. Normal raster rows omit a redundant type badge. Vector/text layer creation and explicit Rasterize remain available in Layers. Vector Editing provides path-edit/correction tools, and the standalone Text tool creates and edits artwork text through the existing object transaction.

The header uses a blend-mode combo and a `ValueSlider` opacity row with a visible track and compact manual-entry field. Document property-edit snapshots support live opacity and eye-column sweeps; previews emit redraws without history entries, release commits one command, and cancellation restores the snapshot. Other drawing, selection and structural edits are blocked during that property gesture. Save/export/settings entry points finish a pending property edit; recovery waits until it ends. The visibility sweep applies the first row's chosen visibility to every crossed row without changing the painting target. Blend-mode wheel/keyboard changes are immediate document edits.

Thumbnail updates are coalesced on a 33 ms single-shot timer. `renderLayerThumbnail` fits only a raster layer's own nontransparent content inside the requested drawing bounds into a small transparent image. Visibility, opacity, locks and blend modes are excluded from that preview. Per-tile alpha extents are cached by image identity, and final thumbnails by tile positions/identities, bounds and requested size, with an 8 MiB image-cache budget. The panel draws the checker behind the image and uses a folder icon for groups; thumbnail generation never allocates a full-canvas buffer.

## Coordinate spaces

1. Artwork coordinates store source drawing pixels. The saved shot-camera transform maps artwork into final output coordinates; layout view uses the identity mapping.
2. Sheet coordinates add the extended drawing area, paper margins and metadata header. `sheetGeometry` defines these rectangles in one place.
3. View coordinates are a transform from sheet space to a widget: translation to the view center, rotation, zoom and translation from the chosen sheet center.
4. The Navigator has its own transform from sheet coordinates to a miniature. Its viewport polygon comes from the inverse canvas transform, so it remains correct at nonzero rotations.

PNG exports use project data directly. Neither export reads a widget screenshot, current zoom, pan, panel state or working-view rotation. The movie renderer composites visible artwork over the configured white/transparent background and omits Notes layers. The 3D drawing camera is evaluated for editor references. The 2D shot camera frames artwork in both previews and exports.

## Persistence

Projects with nondefault audio-finishing metadata use format 23 and `TOONPRO23\n`. Otherwise, multiple shots or nondefault scene names select format 22 and `TOONPRO22\n`; captured extended brush dynamics select format 21 and `TOONPRO21\n`; colored vector resources select format 20 and `TOONPRO20\n`; other projects use format 19 and `TOONPRO19\n`. These signatures are ten bytes long. Versions 10–18 also use ten-byte signatures, while earlier binary versions retain their nine-byte signatures. The manifest and each binary image/model resource are stored as an unsigned big-endian 32-bit byte count, 32 raw SHA-256 checksum bytes, then the payload. The bounded JSON manifest describes movie/shot settings, layer/group nodes with parent IDs, clipping, full/alpha/position locks, blend-mode keys, optional row colors and ordered tile-coordinate pairs, reference image IDs/names/dimensions, each shot's drawing guides/shared guide settings, editable object source data and named selections with feather radii. Artwork PNGs follow in shot, layer and tile-descriptor order; all reference PNGs follow them in shot/reference order. Version 8 added shared grayscale brush resource PNGs after references, in manifest order; version 9 appended deduplicated 3D model blobs after those images. Version 10 adds validated instance rest skeletons in the scene metadata without changing resource order. No base64 pixels are embedded in JSON. Guide and rig data add no binary image payloads. Version 11 adds compressed, checksummed per-instance skin weights in scene-v3 metadata; version 12 adds instance pose metadata in scene-v4 without changing resource order. Version 13 adds validated track/drawing/template/exposure metadata while retaining the existing resource order. Version 14 adds validated layer property channels and path poses without duplicating their source brush resources. Version 15 appends embedded audio resources; version 16 adds camera pose/key metadata without changing binary resource order. Version 17 appends grayscale mask PNGs after audio resources in shot/layer/sorted tile-coordinate order. Versions 18–19 add motion-curve metadata and typed templates/vector cels without changing binary resource order. Version 20 adds RGBA stamp PNGs to the existing brush-resource section without changing section order. Their descriptors include `format: "rgba8"`; grayscale descriptors retain the earlier schema. Version 21 adds response curves, per-stroke jitter and seed preferences to editable brush captures without changing binary section order. Version 22 adds scene labels for movie organization, and version 23 adds strict optional per-clip finishing metadata without changing binary section order. Format 23 also writes the required scene labels even for one default-named shot. Versions 11–23 have a 64 MiB manifest bound; v8–v10 retain 32 MiB and older manifests retain 4 MiB.

The loader validates schema, unique IDs, dimensions, byte limits, checksums, duplicate coordinates, 256 × 256 tile PNG headers and decoded image sizes. Parent links must refer to groups in the same shot, be acyclic and remain within eight group levels. Groups cannot own tiles or raster-only flags. Versions 6–23 require typed `positionLocked`, `blendMode` and `rowColor` fields: blend keys must be one of the twelve implemented modes; row color is an empty string or an opaque `#RRGGBB` value. Reference dimensions/count/aggregate pixels are checked before decoding and the PNG size must match its manifest. Guide types, point counts, bounded coordinates, geometry, colors, settings and per-shot/project budgets are validated before artwork decoding. Guide identifiers share the project's uniqueness domain with shots, layers and references. The loader rejects truncated and trailing data. Tile coordinates can be negative for off-frame artwork. Version 1 JSON projects receive an empty raster layer; v1–v4 acquire empty guide lists. Versions 1–5 default the new layer fields to Normal blending, unlocked position and no row color. Existing hierarchy, artwork, references and guides keep their prior interpretation. Version 7 adds validated layer-kind and object fields plus bounded saved selections. Versions 1–23 load; saves select v19–v23 using the feature predicates above. Colored resources, extended captures, scene metadata and audio finishing disguised as older formats are rejected; versioned signatures prevent older readers from silently discarding these fields or changing replayed behavior. Object render tiles are derived in memory and rebuilt from validated source objects on load; only raster layers contribute tile PNG payloads. `Project::fromJson` parses metadata only; `loadProject` fills the image payloads and validates the complete project.

The storage writer uses QSaveFile to finish a complete checksummed container. `ProjectSave` runs validation, encoding and writing on a worker into an owned sibling temporary file; GUI-thread completion alone publishes it by atomic same-folder replacement. Explicit Save shows progress/cancellation and only marks a matching document generation/revision clean. A 30-second timer starts separate background `.recovery` snapshots while dirty and between artwork gestures. Newer valid snapshots are offered on open. Undo/Redo, project transitions and invalidation cancel stale jobs and remove owned stale recovery; canceled workers cannot publish late. This is periodic recovery, not a per-stroke journal.

Docking and window geometry remain separate machine-local INI data; tool definitions and organization use the adjacent `tools.json` catalog. The Shots panel selects and manages any shot by stable ID, with scene filtering and transient per-shot navigation. Shot order defines movie export order. Timeline playback remains local to the active shot; whole-movie and queued shot exports evaluate their own immutable snapshots.

## Raster and editing model

Raster layers contain a sparse map of 256 × 256 premultiplied RGBA images, keyed by integer tile coordinates. Image copy-on-write shares unmodified tiles across history snapshots. Dabs detach touched tiles, clip to the drawing extent and use source-over painting or destination-out erasing. Notes layers can also paint into paper margins below the header. Rendering excludes Notes independently of their visibility when exporting movie frames.

The shot retains a flat node vector: `parentId` determines hierarchy and vector order determines sibling order, bottom to top. Structural edits move siblings or change parent IDs while descendants retain stable IDs. The tree panel presents the reverse sibling order. Group visibility, full locks, position locks and Notes status apply to descendants. Composition recursively isolates each group per sparse tile, then applies its blend mode and opacity once. The supported `LayerBlendMode` values map to Qt composition modes: Normal, Multiply, Screen, Overlay, Darken, Lighten, Color Dodge, Color Burn, Hard Light, Soft Light, Difference and Exclusion. Layer blending is separate from brush-stroke blending.

Each unclipped base and its following clipped siblings is an isolated run. Normal clipped overlays use SourceAtop to preserve the base alpha. Other modes blend over an opaque copy of the unassociated base color, then restore and premultiply with the original alpha byte; this retains fractional edge coverage while applying the clipped layer's blend and opacity. The base's blend mode and opacity then apply to the complete run. A hidden or excluded base remains a clipping barrier. Groups may be bases but cannot themselves be clipped. The normal and device-resolution transform-preview compositors use the same clipping helper. Completed tile-cache signatures include blend modes, hierarchy, visibility, Notes, clipping, opacity and image identities.

Alpha-locked painting mixes native brush color/blends into original covered pixels while retaining each original alpha byte exactly. It never allocates new artwork tiles or paints into zero-alpha pixels. Erasing is disabled until alpha lock is removed. This applies to moving strokes, symmetry and airbrush through the shared dab engine.

Stroke samples are converted from inverse-transformed canvas coordinates into output-relative pixels. Mouse input supplies full pressure; accepted tablet events use pressure for diameter and avoid synthesized duplicate mouse strokes. Brush flow accumulates over dabs. Spacing is measured along the stroke and carried across input events. One stroke is one undo command; Escape rolls back the live stroke. A tile-budget failure rolls back the entire stroke rather than retaining a partial mark.

Optional stabilization uses a causal low-pass filter parameterized by distance travelled in artwork pixels. Strength 0 passes input through; 1–100 maps to a smoothing length up to 24 px. Exact integration over each linear input segment plus fixed one-pixel spatial sampling keeps results independent of event subdivision. Pressure is interpolated through the same filter. The cursor follows the filtered tip. Release, tool changes, focus loss and working-view changes finish the small remaining gap and commit the gesture; Escape discards it. Higher strength introduces lag and rounds corners. There is no timer-driven continuation after release.

Round tips use ellipse coverage; sampled foreground tips store grayscale masks, with 0 transparent and 255 opaque. Optional `BrushSettings::colorTip` stores premultiplied ARGB32 and overrides the foreground tip mask. Its image alpha supplies the same silhouette used for cursor outlines and vector picking, while its original colors enter accumulation. Color dynamics and foreground tinting do not modify colored stamps. The native brush engine evaluates size/angle/roundness dynamics, input/pose, hardness, texture, secondary masks and coverage effects before composing each stamp. Render-sized sampled sources avoid expanding a high-resolution imported mask for every small dab. Each resulting dab is resampled in local coordinates once and shared across touched tiles, avoiding different image-sampler rounding phases at tile edges. Spacing is a fraction of nominal brush size, carried continuously across input events with a 0.25 px minimum.

Large colored sources have a bounded 8 MiB cache of bases reduced to at most 256 pixels per side; pressure-sized resampling uses those bases instead of repeatedly scanning the imported image. Another 8 MiB cache retains sampled color sizes. Softness filters premultiplied channels and alpha together to avoid dark fringes.

An additional 8 MiB cache reuses resolved tip geometry and optional stamp colors, keyed by image revision, diameter, roundness, angle, hardness and flips. It does not cache away pressure, tilt, jitter or resource edits: those change the key. Texture constants are calculated once per stamp rather than per pixel, and brushes without mask effects skip that processing pass. These optimizations retain the same deterministic dab coverage and painted pixels.

`BrushInput` carries pressure, tilt X/Y, barrel rotation and wheel data. Document interpolates input along spacing samples, resolving manual pose overrides in the engine. Randomness is indexed by stroke seed, stamp index and effect channel so event frequency does not create arbitrary new jitter samples. Unlocked seeds advance between strokes; `BrushSettings::lockRandomSeed` instead selects the saved `randomSeed` without consuming that advancing sequence. The effective seed is captured with editable vector strokes and is shared by live rendering, replay and the active cursor. Tests can independently set the unlocked seed sequence. Color dynamics can use one initial-stroke color or per-tip colors. Symmetry produces transformed copies in the same gesture; guides are view overlays and do not enter exported pixels.

During a stroke, a separate sparse RGBA64 accumulation layer retains higher precision than the final 8-bit raster tiles. The engine recomposites changed rectangles against the original layer snapshot. This separates flow deposition from a stroke opacity cap and avoids repeatedly applying blend modes to the already-composited result. Continuous textures are sampled at final artwork pixel centers after tip transformation, keeping the grain fixed across symmetry copies; per-tip textures move with the stamp. Erasing uses accumulated coverage to remove original alpha. Stroke buffers are discarded on commit/cancel; tile-budget failure rolls the gesture back. Stationary airbrush ticks are driven by a Canvas timer only during an active painting gesture, with the same input, history and tile limits as moving stamps. The working accumulation adds memory beyond stored raster tiles and history.

The cursor uses an analytical circle for ordinary round tips or traces the rendered mask contour for transformed/sampled tips, including holes and separated islands. Soft masks use 20% of peak coverage. Active-stroke state drives dynamic shape previews; continuous textures use the pointer's artwork position. The outline is cached independently of view translation/zoom and never affects saved pixels. The representative pointer previews one tip, not the entire scatter distribution.

While painting, Canvas tracks the active layer's tile image revisions without retaining extra image copies. Changed tiles invalidate corresponding viewport regions, expanded for filtered edge pixels, zoom and rotation. The full layer stack is composited inside those regions, including group opacity and clipping. Nested sheet clips preserve the outer dirty region. Cursor updates cover the old and new tip outlines, including stationary airbrush and guide-constrained input. Commit, cancellation, history and view changes invalidate the complete cache. Unchanged tool/object properties no longer refresh on each live brush sample; layer thumbnails and Navigator still receive document updates. Static sampled cursor contours ignore unrelated stroke indices and direction changes; dynamic masks retain their relevant inputs.

Partial artwork redraw is used with canvas smoothing enabled. Qt's clipped rotated smooth sampling can differ from a full redraw by one 8-bit channel step in the tested cases; repeated redraws do not accumulate that difference. Stored pixels and exports remain identical. With smoothing disabled, Canvas retains full artwork redraws because clipping Qt's nearest-pixel sampler can select a neighboring source pixel at fractional zoom or rotation. That mode still benefits from the brush-engine, cursor and property-refresh changes.

Document edits use QUndoStack with copy-on-write project snapshots and stable before/after selection IDs. The history has a 50-command cap and a conservative memory estimate including reference-image and detached mask-tile changes: exceeding 64 MiB clears older history before adding the newest command. A single large edit may exceed that estimate. Persistent layer masks and color adjustment layers are available through the CPU effects compositor. GPU raster painting is not implemented. Vector and text source objects are available, with derived raster tiles sharing the existing compositor. Stroke blend modes and native brush dynamics are available. Supported modern ABR descriptors map a restricted subset of native settings; texture/dual-brush resources and full Photoshop rendering remain outside that mapping.

## Layer operations and edit guards

Bulk layer APIs accept stable IDs. Selected descendants whose ancestor is also selected are reduced to one root operation; grouping, movement, copying and deletion expand those roots to complete subtrees. `moveLayers` retains sibling order and treats its `beforeId` in bottom-to-top storage order. Copies receive fresh IDs and remapped internal parent links. The UI owns the transient multi-selection; Document history preserves the active layer identity rather than persisting the entire tree selection.

Full locks prevent pixel edits, property changes and destructive structure edits, including inherited locks. Visibility and explicit unlocking remain available; copying a locked source is allowed when its destination ancestors are unlocked. `layerPositionLocked` includes both position and full locks along the ancestry chain and blocks pixel transforms, reordering, reparenting and grouping. Alpha locks are raster-only and do not replace either other lock. Every operation is also gated against an active stroke, transform preview or layer-property edit as appropriate.

Structural changes validate the complete candidate project and preserve existing clipping-base IDs. A move into a descendant, excess depth, removal of the final raster layer, or a changed surviving clipping relationship is rejected. Folder creation requires selected roots from one parent. The single clipped-layer grouping action clears its clipping flag to retain its prior behavior; multi-layer grouping requires the clipping base and its dependent layers to travel together. Add/copy paths enforce layer and tile budgets before commit.

Merge Down requires two visible, unlocked Normal raster siblings with matching effective Notes status, neither clipped nor with a clipped dependent above the active row. It renders their sparse tile union, keeps the lower layer's ID/name, bakes opacity into pixels, resets alpha lock and commits one command. Non-Normal or clipping-dependent pairs are rejected because baking only that pair could alter how it interacts with its backdrop.

Flatten Image renders visible artwork and Notes into separate transparent raster composites. It rejects full locks, mixed artwork/Notes root families, Notes interleaved below artwork, cross-category clipping and backdrop-dependent non-Normal top-level Notes. This preserves both sheet and movie-frame output. Hidden pixels disappear from the result and remain recoverable through Undo. Both merge and flatten allocate only occupied 256 px tiles, check the result before replacing state and remain synchronous CPU operations. They retain other shots, references and drawing-guide data.

## Raster selections and transform previews

`RasterSelection` is transient Document state: an active flag distinguishes an empty selection from unrestricted painting, and an artwork-space QPainterPath plus a 0–100 px feather radius defines coverage. Rectangle, ellipse and lasso/polygon gestures convert through the inverse working view. `RasterSelectionCache` classifies full/empty tiles without bitmaps and caches partial Grayscale8 masks within an 8 MiB budget. Feathering rasterizes a tile halo and applies a separable box blur; overlapping halos make neighboring tiles agree without a document-sized mask. The brush snapshots this immutable selection at stroke start and reuses coverage across dabs; extraction uses the same 0–255 coverage. This keeps sampled brushes, erasers, airbrush and symmetry inside the selected coverage. Selection edits do not dirty the project or create history entries.

Selection gestures capture Replace/Add/Subtract/Intersect mode at press, including keyboard overrides. Path boolean operations and bounded 1–100 px expand/contract operations remain transient. Selections already within drawing bounds skip polygon clipping. Above 4,096 combined elements, boolean edits rasterize hard pixel coverage within a 32-million-pixel work area and trace the result; expand/contract uses a linear-time pixel-cell distance transform with round corners. Failure leaves the previous selection intact. Dense shape gestures preview only the incoming shape until commit. Fill and Clear use the same graded coverage, work on sparse tile copies, and commit one history entry only when pixels change. They preserve the selection, respect inherited locks and visibility, and reject allocation-budget failures before changing the project. Alpha-locked fills preserve exact alpha bytes; Clear requires unlocked alpha.

Canvas caches its rendered artwork at viewport resolution and device pixel ratio. A transparent child draws 1 px animated selection dashes on a 60 ms timer; ordinary borders invalidate a narrow region, while complex borders use a conservative bounded rectangle, and parent repaints blit the cached artwork. Above 4,096 elements, a cached screen-resolution boundary mask carries an animated pattern instead of restroking the complete path on each tick. The timer stops when hidden, when border animation is disabled or when no border is visible. A separate cached shade image clips a reusable screen-space diagonal hatch texture to the drawable area minus the selection; the production header is excluded. Geometry changes rebuild the shade with a textured drawable fill followed by DestinationOut selection coverage, avoiding polygon difference; border animation does not rebuild it. Shade opacity is an independent view-only control. View, document, transform, size/DPR and symmetry changes invalidate the appropriate cache. The child SelectionContextBar follows viewport selection bounds, supports drag/pin/reset/hide, and swaps selection actions for Apply/Cancel during a transform. None of these overlays enter the document compositor or exports.

Transform parameters represent artwork displacement, positive X/Y scale and rotation around the tight bounds of selected painted pixels. Entering Transform splits the active layer into stationary and selected tiles once, sharing original images where possible, retaining the original pixels for the entire gesture. Pointer updates change only the matrix and emit `transformChanged`; they neither rebuild raster tiles nor emit document edits. Canvas and Navigator pass `transformPreview()` to the renderer; preview painting keeps the viewport clip and omits the sheet paper clip so off-paper moving pixels remain visible. Save/export/recovery use committed data. The explicit `displayProject()` snapshot materializes full-resolution transformed pixels lazily and must not be called from interactive painting. Other document edits are blocked while a transform is active. Preview placement is bounded by supported coordinates rather than the drawing extent. Apply intersects output pixels with each layer’s drawing bounds, clips the transformed selection and clears a resulting empty selection, then records one project snapshot command with before/after raster selections; Cancel drops the preview. Menu Undo cancels an active preview before touching history. Save/export/settings require the preview to be resolved, while recovery can still preserve prior committed edits.

Interactive previews composite stationary and transformed selected tiles at the clipped device resolution with nearest-neighbor sampling. Layer/group blend modes, isolated opacity and clipping runs still apply at their original hierarchy positions. Each intermediate buffer is capped at about four million pixels, respecting device pixel ratio; offscreen tiles are culled. Normal rendering caches completed tile composites by layer metadata and image cache keys within 96 MiB, so unchanged pixels survive cursor/Navigator repaints while edits invalidate affected tile signatures.

Apply builds full-resolution pixels from the original source once. Integer translations preserve exact pixel bytes; other affine transforms inverse-sample premultiplied pixels across sparse tile boundaries with bilinear filtering. A source scratch image capped at 64 MiB avoids repeated sparse lookups for common frame sizes, with the original sparse sampler retained for wide extents or allocation failure. Destination tiles are allocated/detached once each. Selected pixels are removed from the original layer and the transformed result is source-over composited onto its untouched remainder. Preview checks transformed bounds against the supported coordinate range. Apply crops filtered destinations to the drawable extent and checks exact tile allocations atomically; failure leaves committed artwork and the pending preview intact. Candidate sampling is bounded to 4096 sparse output tile locations; actual stored project tiles still obey the 1024-tile limit. Full-resolution Apply remains synchronous CPU work.

The current active selection and unapplied preview remain transient. Saving a named selection explicitly stores its stable ID, name, path and feather radius in the shot; up to 64 names and 262,144 path elements per selection are accepted. Named-selection save/delete operations are undoable project edits, while loading a named selection changes only transient selection state.

## Additional drawing engines

`RasterTools` supplies artwork sampling, bounded scanline flood fills, noncontiguous color masks, path rendering, gradients and retouch gestures. Sampling can isolate the active layer, isolate a named reference layer, or composite visible layers through the shared renderer. Flood work is limited to 32 million pixels; tolerance compares premultiplied RGBA channels and optional gap closing uses separable square dilation/erosion. Binary masks become exact pixel-boundary contours with opposite winding for holes, collinear compression, a one-bit-per-pixel visited map and a 262,144-element limit; no general polygon simplification is needed. Bucket-only edge recovery extends at most two pixels into an adjacent antialias ramp and replaces the background contribution when painting on the ink layer; opaque cores and disconnected seed-colored regions remain barriers. Shape/gradient/fill candidates commit atomically after tile checks and preserve alpha locks.

Retouch strokes reserve the Document stroke guard, snapshot once and commit once. Smudge transports neighboring source pixels; Mixer blends that transport with foreground color; Blur averages a local neighborhood; Sharpen applies a bounded unsharp difference; Dodge/Burn adjust RGB while retaining alpha. Pressure scales diameter and strength. Each dab reads an immutable snapshot of the preceding dab, avoiding iteration-order feedback. These are native CPU algorithms rather than a physical pigment simulation.

`EditableObject` stores cubic Bézier nodes or laid-out text, stroke/fill and object transforms. Vector and text layers cache their rasterized output in the existing tile map so layer blending, thumbnails, exports and color sampling share one compositor. Object operations retain editable sources until explicit Rasterize. Fonts are selected by family from the host and are not embedded. Opening text on a machine without the intended font uses Qt font substitution, which can change glyph appearance and layout; explicit rasterization preserves pixels when editability is no longer required.

`AdvancedTransform` adds selected-layer/folder and selection-boundary gestures. Projective matrices preserve vector/text sources; a nine-point mesh maps eight triangles and requires editable layers to be rasterized explicitly. Live previews retain original source tiles. Mesh warp rejects active selections above 4,096 elements before mutation; ordinary matrix transforms remain available, avoiding repeated general polygon clipping on dense Color Range paths. Apply clips raster output and selection geometry, validates coordinate and memory limits, and commits once. Editable vector/text sources remain intact and their derived raster tiles are rebuilt within layer bounds. `ClipboardTools` transfers pixel images with optional internal origin metadata, preserves transparency and supports separate new-layer placement. Details and restrictions are in [drawing tools](drawing-tools.md).

## Perspective drawing guides

`DrawingGuide` and `GuideSettings` are shot data; `drawing_guide.cpp` owns validation and native JSON serialization. Six guide types are supported: convex perspective plane, vanishing point, two-point perspective, parallel ruler, three-point perspective and fisheye. Three-point guides store three vanishing points and a shared grid anchor. Fisheye guides store two ellipse-axis endpoints and a perpendicular-radius handle; the radius uses its perpendicular projection, allowing rotated ellipses without a new serialization shape. `guide_geometry.cpp` computes bounded overlay paths and candidate straight or curved stroke constraints in artwork coordinates. Visible paths are clipped to the view/drawing extent and optional area; parallel-line density is bounded when zoomed out or when handles lie far offscreen.

`GuideTool` owns transient creation points, selection, handle-drag previews and stroke snapping. `GuidePanel` exposes an assistant list with display/lock/snap actions, selected/global property tabs and guide-set import/export. Committed changes go through `Document::replaceProject`; a drag uses a preview and commits once on release. Guide coordinates stay output-relative when paper settings change. Guides paint as editor overlays after cached artwork and are never passed to sheet/movie exports or the raster compositor.

Guide lines use separate viewport image caches for background assistants and the selected assistant. Cache keys include guide data, shared display settings, view geometry, viewport size and device-pixel ratio. Cursor movement and brush dabs reuse these images. Handle dragging draws only the selected assistant live with fast line rasterization; antialiasing returns in the cached final rendering on release. Other guides and artwork remain cached. Lines use physical-pixel hairlines to avoid expensive wide antialiased strokes on high-DPI displays; connected fisheye segments render as polylines to avoid dark segment-end seams. Lost mouse/pen releases, focus loss and document history changes discard uncommitted guide previews. Canvas handles use the shared delayed tooltip surface.

Visibility and snapping are independent. Brush/eraser stroke start captures candidate constraints from enabled guides; initial movement selects one constraint that stays fixed through the stroke. Three-point guides contribute lines through the start toward each vanishing point. Fisheye guides contribute two ellipse-family curves through the start inside the outer ellipse, with point projection following the chosen curve rather than a tangent line. Center-axis constraints are straight; candidates pass through the exact stroke start independently of displayed density. Limited guides require the start point inside the configured area and apply their constraint only while both input and projected points remain inside it, allowing freehand movement outside and resumption on re-entry. Perspective planes also require the start inside the quad. Guide constraints affect the stroke path before stabilization and native brush effects, not every scattered stamp pixel.

After stabilization, fisheye samples are projected back onto the chosen ellipse and subdivided along its arc so sparse pen events do not paint straight chords. The cursor and airbrush use the last painted point. Stationary pressure/pose updates continue both before and after the initial movement chooses a constraint. These changes preserve one undo step for the whole stroke.

Each shot permits 64 guides, and the project permits 256. Points and area bounds must be finite within ±1,000,000 artwork pixels. Subdivisions are integral from 1 to 64; nondegenerate geometry and strict JSON value types prevent invalid grids from entering the document. Native `.toonguides` sets use `toon-pro-guides` version 1 JSON, a 1 MiB read/write limit and atomic replacement. Import gives every appended guide a fresh ID and adopts the imported global settings. The `three-point` and `fisheye` type keys added in 0.10 used the version 5 project and version 1 guide-set schemas. The 0.11 project container adds layer metadata in version 6 while retaining these guide fields and guide-set version 1. Existing 0.9 files remain readable, and older readers reject unknown guide types without discarding guide data. Krita's `.paintingassistant` format is not supported. See [guide interactions and limits](guides.md).

## Brush library and ABR boundary

`BrushLibrary` is independent of the document. It combines immutable built-in source presets, including the native starter pack, with custom presets in machine-local `brushes.json`, beside workspace settings. Version 2 presets contain all native brush settings, smoothing, optional primary/texture/secondary grayscale resources, source identity and compatibility notes. Version 3 adds the optional `colorTip` PNG; writers select it when colored presets are present without extended dynamics. Version 4 carries extended response, rotation, jitter-cadence and seed settings; ordinary presets retain version 2. Manager-created brush tools live in the catalog rather than adding duplicate source-library templates. Foreground/background colors remain shared workspace choices and are excluded from saved preset/tool identity. ToolCatalog seeds individual brush tools from these templates. ToolSession applies their settings through Canvas and synchronizes Tool Properties without entering artwork history. Each catalog tool restores its own texture, even with Protect Texture enabled. Raster strokes retain pixels; vector brush strokes retain editable source plus embedded brush resources. Both remain usable after removing the library or source ABR.

Library writes use QSaveFile. Loading validates the versioned JSON schema, preset identities, enum/numeric settings, PNG dimensions, encoded sizes and aggregate resource cost across primary, colored, texture and secondary images before replacement. The 64 MiB library resource budget counts grayscale pixels as one byte and RGBA pixels as four; resources are at most 2048 pixels per side, with 6 MiB grayscale or 17 MiB colored PNG limits. Colored images must contain visible, valid premultiplied pixels. Visibility/format validation is cached by immutable image identity. A failed load preserves the in-memory presets and prevents writes to the damaged file. Imports enter the library as one atomic batch. Images are embedded as bounded base64 PNGs, independently of the project container. Version 1 libraries migrate in memory and upgrade on a successful edit, retaining their legacy flow semantics.

`importAbr` is a bounded binary parser, separate from the UI and renderer. It extracts raw/PackBits 8-bit sampled tips from ABR v1, v2, v6.1, v6.2, v10.1 and v10.2, rejects malformed structures and reports skipped records. Large source tips are decoded one at a time and smoothly resized to at most 1024 pixels on the longest edge, with original/imported dimensions retained in compatibility notes. Source and stored-pixel budgets are checked independently. A separate bounded action-descriptor reader maps modern preset names, sampled-tip UUID associations, computed round geometry and selected size/angle/roundness, opacity/flow and scatter dynamics into native settings. Enabled source flags gate those dynamics. Missing, repeated or unsupported sample identifiers never fall back to record-position matching. Unknown descriptor types/versions retain supported sampled tips with native defaults and a warning; malformed known descriptors reject the import. Texture resources, dual brushes, color dynamics and full Photoshop rendering are unsupported. Source identity includes the input file SHA-256 and sample/preset identity; version 2 retains sample names, while imports without supported modern names use explicit fallbacks. Exact support, limits and fixture provenance are recorded in [Brush compatibility](brush-compatibility.md).

## Editable brush strokes in 0.14

`Document` uses the same dab renderer for raster painting and vector-brush capture. A vector object retains resolved brush settings, deterministic random seed, complete sampled tablet input and original dab positions, together with a coarser editable Bézier centerline. A geometry signature permits exact original-position replay; edited geometry maps normalized sample distances onto the current centerline. Width factors interpolate along that path, while object color, nominal width and opacity override the captured brush style. Colored stamps retain their embedded colors instead of applying the object stroke color. Selection geometry/feather and alpha-lock context are retained for replay.

`rebuildObjectLayer` renders objects in order because stroke blend modes and alpha locking depend on preceding artwork. Its bounded prefix cache avoids rerendering an unchanged prefix while editing the final stroke. Version 0.14.3 also caches each eligible vector stroke's accumulated paint before compositing with preceding artwork. Replaying unchanged later strokes uses the same brush compositor, including blend modes, dissolve and alpha locks, rather than evaluating their dabs again. The source object and drawing bounds must match exactly. The 64 MiB cache accounts for retained source/resources and paint; entries are limited to 32 tiles. Oversized strokes fall back to streaming replay. `Document::endStroke` seeds eligible entries from its existing 16-bit accumulation after source validation, avoiding a cold replay on the first edit. Cache contents are transient and do not change project storage. Source resources use image copy-on-write; history accounting includes retained geometry, samples, width profiles and image resources. A vector stroke is not exported as an SVG brush: the source remains editable while the shared brush renderer produces tiled pixels.

Correction brushes map source anchors and controls through captured symmetry and then the object transform. Width uses the minimum distance across copies and applies once per source node; simplify protects nodes outside the swept region and tests deviation across all copies. Width resampling uses the longest transformed copy. These edits retain one shared source and normal gesture undo/cancel behavior. Scatter offsets do not define additional correction centerlines.

Sampled-brush hit testing rasterizes candidate alpha using captured dab settings, symmetry, object transforms, continuous texture coordinates and selection masks. A query processes one destination tile at a time with 16-bit accumulated alpha, including faint buildup, 8-bit output rounding and dissolve. Ordinary footprints retain the renderer's full stamp origin to match Qt sampling. ## Skin binding and weight editing in 0.18.0

`Skin3D` is optional instance-owned data: an ordered joint-ID table and four normalized joint/weight slots per mesh vertex. Shared model geometry and global-library assets stay immutable. Automatic binding measures model-local vertices against rest-joint bone segments, retains the nearest four influences and normalizes inverse-squared-distance weights. Binding runs through Qt Concurrent with cancellation, target/generation checks and full candidate validation before a single document commit. Rest-joint edits require undoable unbinding first.

`SkinPaintProjection` builds a bounded 1024 × 1024 depth surface and widget-space vertex bins off the UI thread. It accounts for the opaque selected heat mesh, other visible objects, renderer-matched frustum clipping and ordinary occluder alpha cutouts. Brush queries visit nearby bins rather than traversing the scene. Camera/view changes coalesce while a build is pending; painting waits for the current projection. Visibility is an approximation at the bounded depth resolution, and occluder alpha textures use nearest sampling when textures are enabled. Painting edits vertices, so very coarse meshes offer fewer correction points.

The controller stages weight edits separately from Document until release. Add/Subtract adjust the selected influence with radial falloff and tablet pressure; Smooth blends toward the falloff-weighted mean of visible vertices under that brush. A stroke uses its original weights and maximum per-vertex coverage to avoid dependence on pointer-event density. Remaining influences are normalized and capped at four. A sole influence cannot be reduced without first adding another joint's influence; an otherwise unchanged stroke reports that restriction once. Release commits one undo command, Escape discards it, and Save/tool changes resolve the active gesture.

`Scene3DRenderOptions` derives only the selected instance's temporary geometry and heat colors on the renderer worker. A selected-joint XYZ bend check uses linear blend skinning around the rest pivot, including descendant joints. The temporary rotation is not a saved pose; reset it before painting. Ordinary scene keys omit rig/weight metadata, while preview keys include the selected joint, a weight revision and bend. A retained copy-on-write skin snapshot lets the controller detect changed weight buffers in O(mesh count) and advance a monotonic revision; it never fingerprints the full skin during interactive preview requests. The renderer accepts that service-scoped revision for request and geometry identity, with a full-content fallback for callers without a revision. Display cache keys additionally include a controller UUID to isolate separate canvases. `Scene3DPreviewScope` selects the transient image only for its owning Canvas and Navigator, keeping ordinary reference caches and exports independent. Weight render requests are coalesced on a 33 ms timer; this bounds request frequency rather than guaranteeing a frame rate.

Scene version 3 explicitly stores null or validated skin metadata per instance. Each vertex packs four 16-bit joint indices and four 32-bit weights into 24 bytes, compressed with zlib and protected by a SHA-256 checksum. Load checks decoded counts and the 48 MiB aggregate skin budget before inflation, then exact output size, trailing bytes, influence normalization, joint references and hydrated mesh vertex counts. Each skin permits at most one million vertices. Format-11 projects preserve these weights and read formats 1–10; older-format files claiming skin fields are rejected. Skin changes participate in history memory accounting. This milestone did not introduce imported glTF skins, FK/IK controls, reusable pose assets or animation.

Group transforms affect exposed content only. Protected containers and ownership boundaries are validated by Document; general flattening cannot destroy a timeline. Frame switches select the corresponding template role where possible and clear transient pixel selections.

Playback uses monotonic elapsed time at project FPS, skipping display frames when necessary instead of slowing the shot clock. The canvas reuses its viewport image across unchanged held drawings. Onion skin is a bounded viewport overlay showing one previous and next distinct drawing from the selected track; static backgrounds, Notes and repeated exposures of the current drawing do not become ghosts. It is suspended during playback and excluded from exports. PNG-sequence export renders every requested frame into a new/empty directory with atomic per-file writes, progress and cancellation; completed frames remain after cancellation.

Format 13 serializes only canonical artwork and animation metadata. Limits are 16 animated tracks, 256 drawings, 16,384 exposures and 4,096 stored layer/group nodes per shot, with 64 nodes per drawing and 64 static nodes. At the 0.20 milestone, the 1,024-tile project pixel budget, 64 MiB conservative history budget, 50-command history limit and synchronous save/recovery remained in place; 0.35 moves snapshot saving to a worker without raising those limits. The 0.20 milestone edited the first shot; at that release, multi-shot navigation, audio, property interpolation, animated 3D and encoded video were not implemented. The following 0.21 section adds property interpolation.


## Property animation in 0.21.0

`Shot.layerAnimations` is separate from drawing ownership/exposures. A stable layer ID targets scalar channels for X/Y translation, X/Y scale, rotation and opacity, plus vector-object path channels. Scalars are additive translation/rotation and multiplicative scale/opacity over canonical artwork; a fixed layer pivot controls scale/rotation. Property times use absolute shot frames, including on exposed drawing sublayers. Duplicating a drawing or layer clones its property data with remapped IDs while keeping key times; removing the source layer prunes its channels in the same undo command. Merge/flatten guards avoid discarding animation.

`property_animation` evaluates sorted unique keys with endpoint holds and Hold, Linear, EaseIn, EaseOut or EaseInOut outgoing interpolation. Enabling a channel adds a baseline key at zero and the current frame if later. `Document` property gestures snapshot once, preview live and commit/cancel once, independently of transient playhead/Source state. Locks, numeric bounds, topology and target ownership are validated before accepting edits. Unknown schema fields, duplicate channels/times, missing targets and old-format disguised metadata are rejected.

Path poses store Bézier nodes, width factors, affine transform, stroke/fill colors, width and opacity. Captured brush images, seed and samples remain on the canonical object. Poses must retain the source object, node correspondence/count, open/closed flag, brush source and stroke/fill presence. Animated path source mutation is blocked while its channel remains enabled. Affine pose transforms interpolate decomposed translation, shortest-angle rotation, scale and shear; differing determinant signs require Hold on the outgoing key. This does not implement arbitrary topology matching or 3D morph targets.

`evaluateLayers` first filters drawing exposures and then evaluates property metadata. Local transforms use transient `RasterLayer.renderTransform`; the compositor composes ancestor matrices and keeps opacity/clipping/blending in their layer/group boundaries. Source tiles are not resampled into persistent animated frames. Morph evaluation rebuilds derived object tiles and reuses a bounded thread-local cache (128 MiB tile cost). Canvas, Navigator and exports use the same frame evaluator; failed morph rendering supplies a readable error instead of silently exporting canonical source art. Animated shots include time in the canvas display key.

`ObjectTools` and Path Edit evaluate the current path for selection, bounds, node/style editing and auto-key gestures, writing poses while leaving canonical geometry unchanged. The separate `KeyframeTransformTool` supplies animated canvas movement, scale and rotation. `Document.keyframeSourceEditing` displays original geometry/positions for destructive drawing operations; playback exits this mode and exports always evaluate animation. Source edits on already animated paths require first disabling their morph channel. The Source flag and transient render matrices are not persisted.

`FramePropertiesPanel` contains Drawing and Animation tabs. The selected layer's enabled scalar/path lanes appear under its track in Timeline; dragging key diamonds retimes without replacing occupied keys. Scalar controls use the shared ValueSlider and draft-resolution flow. Save flushes pending numeric edits, Undo cancels an unfinished gesture before history, and playback/scrubbing finish edits through `TimelineController`.

Format 14 keeps the existing resource order, adding layer-animation metadata to the bounded manifest. Per shot, property animation permits 1,024 targets, 16,384 combined scalar/path keys and 262,144 stored pose nodes, subject to existing layer/manifest/tile limits. History budgeting counts detached pose/channel data without re-counting brush images. Frames, channels, topology, bounds and resource identity survive save/reopen and recovery; formats 1–13 load without property channels. Audio, camera/rig/3D keys, graph editors, multiple-shot editing and encoded video remain outside this milestone.


## Audio in 0.24.0

`Shot.audioClips` stores stable clip IDs, frame-based placement, sample-based source offsets/lengths, gain and mute independently of drawing layers. `AudioAsset` holds immutable 48 kHz stereo S16LE samples, a content hash and cached peak levels; instances and history share those assets. Validation bounds source and aggregate PCM bytes, clip counts, offsets, IDs and finite gain. Source PCM is never rewritten by clip edits.

`AudioImport` uses asynchronous Qt Multimedia decoding, then hashes and builds waveform peaks in a worker. Cancellation generations discard stale results. `TimelineController` retains completed imports while artwork gestures, draft edits, playback or modal dialogs are active, allowing the current interaction to finish before inserting the clip. Loading another project cancels imports. The timeline and Audio properties keep draft timing separate from document state until one atomic history command commits.

`AudioMixStream` mixes clipped source intervals into a fixed 1,024-frame scratch buffer. Overlaps sum with per-clip gain, mute filters clips, and the output is clamped to signed PCM/float range. Loop boundaries use rounded sample positions at the project FPS. `AudioPlayback` supplies the QAudioSink processed-sample clock to the timeline; no-output or failed/stalled devices fall back to monotonic silent playback with readable feedback. Stop discards queued buffers. No whole-shot mixed PCM allocation or background playback is retained after stopping.

Format 15 appends deduplicated PCM resource records after existing model records, using the bounded manifest, checksums and atomic save/recovery container. Formats 1–14 migrate on save. PCM is limited to 128 MiB per source and 256 MiB per project, with at most 64 clips per shot; existing total-container and history limits still apply. Audio counts toward the conservative 64 MiB Undo budget, so large imports can shorten retained history. PNG exports remain silent. Version 0.25 added video encoding below; 0.33 later added fades, gain automation, audible scrubbing and standalone WAV export. Time stretching and recording remain unimplemented.


## Offline video export in 0.25.0

`VideoExportSettings` defines a shot index, inclusive absolute source range, even 16–4096 output dimensions, three quality levels and audio inclusion. Defaults fit oversized projects within the encoder limit. `renderVideoExportFrame` evaluates existing drawing/property/path animation at the original project dimensions, then composites it over an opaque white, aspect-fitted RGBA output. It never changes the project dimensions to simulate resizing. Movie-only exclusions and the original PNG render path remain intact.

`VideoExport` owns a copy-on-write project snapshot and an independent worker thread. The worker attaches `QVideoFrameInput` and optional `QAudioBufferInput` to a `QMediaCaptureSession`/`QMediaRecorder`, checks MP4 H.264/AAC availability and verifies the resolved codec choice. Frame PTS comes directly from the relative frame index at project FPS, without accumulated rounding. Audio uses the existing `AudioMixStream`, capped at the difference between rounded absolute start/end sample positions. This preserves nonzero-range alignment at fractional FPS, including cases where rounding the duration alone would add a sample.

The pump submits one frame or 2,048-sample audio chunk per event turn. Rejected inputs remain pending until the corresponding readiness signal; indices advance only after acceptance. It keeps stream lead within 250 ms and retains at most one pending input of each type. Qt/codec queues and per-thread render caches add their own bounded memory; this is not a guarantee of constant total RAM independent of resolution. Vector replay/prefix/resource-ID caches are thread-local, so worker rendering and GUI edits cannot mutate shared cache entries. Allocation failures return a failed frame before constructing a painter.

For ordinary exports, a `QSaveFile` with direct-write fallback disabled is the recorder output device. Empty input buffers mark end-of-stream, and automatic stop drains accepted data. Only a clean finalized recorder can commit the destination. Cancellation, validation/encoder/render errors and incomplete output cancel the temporary file; existing output remains intact. A 60-second inactivity guard requests stop if the encoder ceases making progress. Cancellation is checked between rendering/submission units; an individual rendering or platform finalization call cannot be forcibly interrupted. Destruction requests cancellation and waits up to five seconds, leaving any slower worker self-cleaning rather than terminating its thread or closing its output under the encoder.

Qt 6.10.3 internally stores recorder FPS as an integer even though the public setter accepts a fraction. Multi-frame input PTS still follows the requested FPS; encoded timestamps are independently quantized to the codec time base. A 300-frame 29.97 FPS check found a maximum 17.41 microsecond PTS error, without accumulation. Short fractional clips may report an approximate nominal/average rate due to this time-base rounding.

For a fractional-FPS **single-frame** export, Qt instead estimates the only packet's duration from that truncated integer rate. This case uses a write/seek-capped 80 MiB memory device, then `correctSingleFrameMp4Timing` validates the completed Qt-generated file before changing fixed-width timing fields. The finalizer requires one video sample/chunk, at most one audio track, supported version-0/1 headers/edit lists, zero video composition offset and bounded non-fragmented boxes. Metadata is capped at 1 MiB and traversal at 4,096 boxes. Unsupported layouts fail before publishing.

The video clock becomes a reduced rational derived from FPS to six decimal places; the movie clock becomes 1 MHz. Video sample/header/edit duration is corrected, while audio track/edit durations are rescaled into movie units without changing audio sample timing or priming offsets. Atom sizes, media bytes and chunk offsets stay unchanged. The corrected buffer is copied to QSaveFile in 1 MiB chunks with cancellation checks and committed only on success. This avoids a new external encoder dependency. Layouts are grounded in the official [FFmpeg 7.1.3 MOV writer](https://github.com/FFmpeg/FFmpeg/blob/n7.1.3/libavformat/movenc.c); the underlying Qt rate field is in [QPlatformMediaRecorder](https://github.com/qt/qtmultimedia/blob/v6.10.3/src/multimedia/platform/qplatformmediarecorder_p.h).

AAC packet padding can extend reported audio/container duration by less than one 1,024-sample block on the tested backend; video count and input sample endpoints remain exact. Qt exposes no public AAC trailing-padding trim control. Export uses no audio output device or realtime playback clock. Export settings are transient; video export itself adds no saved project metadata. Camera animation adds format 16 as described below. The UI offers full/custom range tabs, an explicit playback-range copy action, compact size controls, quality tabs, audio inclusion, a destination chooser, progress and cancellation. The nonnative save chooser defers all replacement confirmation to Export, avoiding duplicate macOS prompts.

API references: [Qt 6.10 video input](https://doc.qt.io/qt-6.10/qvideoframeinput.html), [audio input](https://doc.qt.io/qt-6.10/qaudiobufferinput.html), and [media recorder](https://doc.qt.io/qt-6.10/qmediarecorder.html). The application uses the existing Qt Multimedia FFmpeg runtime; external FFmpeg tools are used only for independent development verification.


## Shot and reference cameras in 0.26.0

`Shot.camera2D` stores center-relative position, uniform zoom and rotation; optional `camera2DKeys` hold full poses with the existing outgoing interpolation modes. `sceneCameraAnimations` targets the shared Scene3D layer by stable ID. Its keys store target/yaw/pitch/distance/FOV/orthographic height, while projection type and lock remain on the source scene camera. Evaluation uses the same integer shot frame as drawing exposures and layer/path keys. Angles interpolate unwrapped to preserve deliberate turns. Endpoints hold; keys are sorted, unique, bounded to the shot and limited to 16,384 combined camera keys.

`shotCameraTransform` maps world artwork to fixed output pixels: translate camera center to the origin, rotate opposite the camera, scale uniformly, then translate to the output center. `paintSheet`, movie rendering, and Canvas input/overlays share this transform. Canvas navigation remains an independent transform. The inverse camera maps visible output bounds back to world space before vector rasterization, allowing off-frame objects to enter the output. Raster pixels remain stored in source coordinates; a moving camera does not alter source geometry or tile allocation. Brush cursor scale/orientation and tablet tilt use the combined camera/navigation mapping. Neighbor onion poses use the current camera and bounded visible crop.

`CameraTool` edits a source-layout rectangle through move, uniform zoom and continuous rotation gestures. Camera view applies evaluated framing to artwork; layout view shows source space and the camera outline. Both are transient workspace modes, separate from layer Source artwork mode. Playback selects camera view. Navigator renders the same view mode; exports always evaluate the camera, without editor handles.

`Scene3DController::scene()` exposes a cached evaluated scene for rendering, picking and rig/skin/pose projections. Base scene data remains separate for edits. Frame changes request the evaluated reference and reject stale render results; an older camera image is never published under a new camera cache key. Pending reference images are absent until ready. The scene camera renders a finite reference image first, followed by the common 2D transform; 2D panning cannot reveal geometry outside that image. Reference-only layers stay excluded from movie and sheet exports.

Document camera transactions snapshot immutable project data, preview from the original gesture and commit one history entry. Returning to the original pose restores the exact original key set. Static edits change the base pose; enabled animation writes the current key. Disabling animation or deleting its last key bakes the displayed pose to the base. Explicit timeline key kinds distinguish layer, 2D-camera and 3D-camera references; batch move/delete/copy/paste validates locks, collisions, bounds and budgets atomically. Scene removal prunes its camera keys. The one-Scene3D-layer-per-shot limit remains. Direct scene-layer duplication is unsupported; whole-shot duplication remaps scene instances and camera targets as described below.

Format 16 adds bounded camera metadata without changing binary resource order or Scene3D schema 4. Formats 1–15 load with default framing and no camera keys, and camera metadata disguised as an older format is rejected. Camera history cost is included in the existing conservative budget. Current frame, camera selection, camera/layout view and navigation are not saved. Save/export/frame/tool transitions resolve drafts; Undo/Escape cancels an unfinished camera gesture before changing committed history.


## Effects and compositing in 0.27.0

`RasterLayer` carries `LayerEffects`, an optional sparse `LayerMask` and an adjustment flag. Adjustment nodes retain Raster kind for compatibility but contain no source pixels/objects. Document transactions validate these fields, enforce mask budgets, account for detached mask tiles in history and resolve effects drafts before target/frame changes. `MaskTool` inverse-maps the evaluated camera and layer hierarchy, paints a separate source-local grayscale mask and commits one history operation. `EffectsPanel` shares ValueSlider drafts and the workspace save/cancel lifecycle; shadow placement also uses a spatial pad.

`EffectCompositor` renders bounded output tiles with source-space filter halos and group isolation. It applies mask → color → blur → shadow/glow → opacity/blend/clipping. Adjustment nodes interpolate corrected lower-sibling color while retaining exact backdrop alpha. Layer/folder transforms apply to their finished local composition; camera transformation remains in sheet/output rendering. Editable vector/text geometry is rerasterized using inverse crops expanded through each ancestor's filter support. No-effect and neutral-effect stacks retain the original renderer.

A thread-local 64 MiB cache keys output tiles by source/mask image revisions, all effects/structure/opacity/blend/transforms, annotations, scene preview and smoothing. Destructive transform previews bypass persistent output caching. Per-region and working-memory guards propagate errors through the existing keyframe/sheet/export error path. Brush strokes on affected stacks invalidate the viewport so source-tile-only redraws cannot leave stale halos. Masks and effect parameters were static metadata in 0.27; 0.73 adds the timeline channels described below.

Format 17 retains binary sections from format 16 and appends checksummed grayscale mask resources after audio. Masks validate dimensions, format, coordinates, descriptor order and a project-wide 1,024-tile/64 MiB limit. Disabled settings round-trip; malformed metadata or damaged resources reject the whole load. Formats 1–16 remain readable, while new fields disguised in older manifests are rejected.


## Timeline improvements (0.29)

`timeline_ripple` builds a bounded piecewise frame mapping and applies it to a shot candidate. It splits exposure/audio intervals, maps existing key structures intact, checks affected ancestry/descendant locks, prunes orphan ownership and validates the final timeline before replacing the candidate. Document validates and commits once, reporting an explicit changed flag; the controller resolves drafts, remaps the workspace range and clears stale key selection. Insertion/deletion changes duration; range movement retains it. Interpolated segments are retimed, without generating synthetic boundary keys. Audio trimming uses the shared frame-to-sample conversion and retains immutable assets.

`DrawingTemplateSlot.kind` defaults to Raster and permits Vector. Format 19 writes the optional kind for vector roles; older formats reject typed recipes or vector-owned cels. Role mappings remain hints so rasterizing an existing cel does not invalidate its track recipe. New drawing creation follows the recipe; duplicates retain source geometry and resources. `DrawingTemplateLibrary` independently stores bounded version-1 recipes beside workspace settings, using atomic writes and a loaded-byte comparison to prevent overwriting an externally changed library.

`OnionSkinSettings` is workspace state, validated independently of project JSON. Distinct drawing samples are selected per direction, skipping the current/repeated drawing and hidden containers. Their layer/path poses evaluate at the sampled frame through the current camera. Canvas caches a viewport-sized combined overlay; settings changes invalidate only view caches. Dialog changes preview directly, cancellation restores the opening state and accepted settings persist through MainWindow. Export never reads these preferences.


## Drawing input delivery (0.29.1)

Application startup calls `configureDrawingInput()` before opening windows. Qt high-frequency/tablet compression is disabled explicitly. On macOS, an Objective-C++ adapter independently sets AppKit's `mouseCoalescingEnabled` to false: this process-local setting also governs tablet and dragged-mouse events, and is separate from Qt's compression attributes. Input sample preservation does not disable QWidget update merging or alter stroke geometry/filtering. Queued event tests verify pressure-aware raster/vector curve parity and independent stroke histories; the macOS test checks the native property directly.

## Live brush notifications (0.29.2)

`Document::strokeUpdated` reports the first dab, continued stroke samples and stationary airbrush ticks. Canvas alone consumes this signal to invalidate the artwork preview. It does not forward `Canvas::documentChanged`, rebuild panel controls, render thumbnails or request unrelated tool overlays. `Document::changed` remains the general notification for committed/cancelled strokes, including no-op completion, and other document edits. Existing document mutation guards still protect an active gesture while controls retain their appearance.

Queued layer-thumbnail work checks `strokeActive()` and waits for the terminal notification to schedule another refresh. Selection border animation pauses while painting; brush tool eligibility is reused during an accepted gesture instead of traversing animation ownership for every cursor outline. Input samples, pressure, spacing, stabilization, artwork and history semantics are unchanged. Nearest-neighbor display and effects retain their existing full-artwork cache invalidation paths. Full-workspace tests exercise drawing with visible Timeline/Frame Properties, stable controls, deferred thumbnails and terminal refreshes; synthetic event delivery is not physical tablet verification.


### Multiple shots (0.32)

`Document` owns a stable active-shot ID and resolves its index after every history change. Editing code uses `activeShot()`/`activeShotIndex()`; per-shot frame/layer/animation-track navigation is transient. `ProjectCommand` records before/after shot IDs and reveals the appropriate shot for Undo/Redo. Shot transitions clear selection/caches and synchronize canvas, timeline, 3D selection and panels through `shotChanged`. The Shots panel resolves workspace drafts before navigation or mutation.

Shot duplication remaps owned layer/object/track/drawing/exposure IDs, property/path targets, scene-camera targets, guide/reference/selection/audio IDs and 3D instance/joint references. Immutable image/audio/model resources remain shared until edited. Project shot order is movie order; `Shot.scene` is a bounded saved label. Multiple shots or nondefault scenes require format 22, unless nondefault audio-finishing metadata requires format 23. Single-shot/default-scene saves without audio finishing retain formats 19–21 as required by brush data.

Movie export maps global frames to local shot frames and streams audio in bounded blocks using globally rounded cut sample boundaries, avoiding fractional-FPS drift. `VideoExportQueue` serializes individual immutable-snapshot jobs, reports completed/skipped/canceled/failed outcomes and requires explicit overwrite approval. Existing atomic video publication and bounded frame buffering remain in use.


## Finishing, libraries and responsive saves (0.33–0.35)

Audio finishing extends immutable clip metadata with source-sample fade anchors and sorted bounded gain keys. Any nondefault finishing metadata selects format 23, including inactive retained gain keys or nondefault curves/anchors. Keys use absolute source-sample positions, linearly interpolate amplitude and hold outside their range; enabled automation replaces static clip gain. Trims/ripple edits materialize fade anchors before changing visible edges, preserving their source alignment. One sample mixer serves live playback and finite export; WAV export has a bounded worker buffer and atomic publication. `AudioScrub` keeps an 80 ms preview and replaces pending seeks instead of accumulating them. Workspace-only preferences stay outside project history.

`PaletteLibrary` persists named swatches in a separate atomic global library with external-writer protection. Modern ABR descriptors use a bounded typed parser; UUIDs associate presets with sampled tips, and a restricted mapping produces native BrushSettings plus compatibility details. Tool-catalog version 8 adds the standalone Text tool once, while preserving subsequent removals. Inline text edits use the existing object edit transaction.

`ProjectSave` snapshots implicitly shared project data on the GUI thread, then validates, compresses and writes an owned sibling temporary file in a worker. The GUI completion alone publishes by atomic same-folder replacement. Cancellation, destruction and invalidated recovery can therefore never publish late. Cooperative checks bound cancellation between resource encodes; the current individual encode may finish before stopping. Existing destination permissions are retained.

Recovery never captures an unfinished drawing gesture. Undo/Redo invalidates in-flight and owned published recovery snapshots. Explicit Save remains a modal progress/cancel operation while its worker runs; it marks history clean only if the document generation and revision still match the saved snapshot. New edits during the nested save loop keep the document dirty and prevent a pending navigation from discarding them. No raster/resource limits were raised for these changes.


## Animated effects and masks (0.73)

The scalar-property registry retains the original six enum identities and adds 16 effect and nine mask channels. Numeric channels share existing interpolation/easing; seven boolean channels validate exact 0/1 values with Hold and no easing or spatial handles. Missing effect/mask channels evaluate their saved source property. Evaluated values are absolute overrides; transform/opacity channels retain their existing neutral contribution semantics.

`Document` accepts key-aware Effects transactions. An inspector draft restores keyed source fields and writes only changed evaluated values as keys at the captured frame. Unkeyed fields remain static, including shadow/glow colors. One transaction can update both kinds, with one Undo and no-op/cancel protection. Source-only callers (mask painting and existing Auto Actions) retain their original behavior. Removing a mask prunes its channels in the same undoable commit.

`LayerMask` adds an independent static pivot, position, scale, rotation, strength, feather and inversion. Painting inverse-maps the evaluated mask and layer transforms, respects selection and inversion, and changes the shared source pixels without baking placement keys. Singular transforms block painting and sample the mask default for rendering. Feather sampling uses source-space halos and a bounded 32 MiB per-thread tile cache; output cache keys include all mask properties and source revisions.

The keyframe renderer evaluates effects and masks before calculating effect activity and source halos. Canvas and Navigator detect compositing channels even when their static switches are off, including reachable Symbol definitions. Keyframe gestures use coalesced background Draft work and Exact refinement. Animated/Symbol draft reduction reuses the guarded playback coordinate reducer, scaling relevant scalar keys, pivots and mask/effect pixel extents alongside artwork. Existing unsafe cases use the full-quality worker fallback; exports remain exact.

Format 36 is selected only for effect/mask channels or nondefault mask properties, including nested Symbols. Legacy default masks retain their old JSON shape and existing feature-based formats. File/container validation rejects new fields disguised as an older format; resource order and shared mask-image storage remain unchanged.

`project_templates` builds fresh movie/shot/layer identities for Blank, Illustration, Anime, Storyboard and Animatic.
